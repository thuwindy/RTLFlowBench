# 目前选取的五个 RTL 工作流

我们比较模型如何被组织、使用工具、调试并交付结果，而不是只比较一次模型回答。
当前队列包括两个项目内对照系统和三个外部开源工作流。**入选不等于已通过本版本十二题运行检查。**

| 系统 | 方法与选取理由 | 接入时必须注意 |
|---|---|---|
| ChipFlow | 本项目的设计契约、Critic/Judge、PatchPlan、受控执行和 EDA 反馈链路；检查评审与安全机制的收益及成本 | 它是被测对象，不是出题或评分基准；公共预览不含其完整 runtime |
| 同模型 vanilla agent | 项目内普通 agent 对照，观察复杂工作流相对普通代理的增益；不是另一款上游产品 | 不默认等于一次性生成；循环、工具、提示和停止策略须由 runtime 锁明确 |
| MAGE | 多 agent RTL 生成系统，代表协作生成与反馈迭代路线 | 测试输入必须严格映射到公开允许材料，不能提供 hidden testbench |
| VerilogCoder | 图式规划与 AST 波形追踪辅助的 Verilog agent，代表显式规划和波形调试路线 | 上游接口涉及规格与 TB；不得补入私有测试或专属解题提示 |
| HDLAgent | 硬件描述语言生成与工具反馈的 agent/CLI，引入另一种工具闭环实现 | 支持范围必须由固定源码和真实运行证明，不能从名称推断 |

## 为什么所有系统都做十二题？

主结果必须保留全部系统 × 十二题矩阵，不让某个系统只做擅长的题。
失败、能力不支持、基础设施故障及缺失原因都保留；支持子集条件分只能辅助分析。
这才能测出工作流能力边界，而不是为每个系统定制一套试卷。

控制实验拟统一 DeepSeek 配置，确切模型 ID、provider、采样、预算及 runtime 以冻结的实验锁为准，
本页不声称当前已经全部锁定或可用。同模型减少模型选择的混杂，但不能消除模型与工作流的交互。
因此这是统一模型条件下的比较，不是复现每篇论文最佳设置，也不是模型无关的绝对排名。

## Adapter 不替系统解题

只允许公共格式转换、启动和产物收集，不允许参考 RTL、hidden oracle、题目解法或额外设计知识。
不能偷偷改用另一个 agent 代替 native 工作流；上游需要缺失输入时，要区分接入问题与能力边界。

每个系统扩批前必须证明：

1. 固定上游 commit、补丁哈希、依赖与容器身份。
2. 公共输入完整，私有材料不可见，native 入口确实执行。
3. 工具反馈有效，重复错误、超时和预算停止生效。
4. 新生成产物正确导出 submission，没有误交历史文件。
5. 真实 token/cache、调用数、耗时和干预可追溯；缺失按策略停止，不填零。

启动成功、交卷成功、evaluator 通过是三个不同阶段。先修运行故障，再讨论能力与难度。
